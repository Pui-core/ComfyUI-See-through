# VTube StudioのモデルをOBSへ透過で取り込む

Issue #19の設定記録です。[修正版モデル](live2d-polish.md)をVTube Studioで動かし、その映像をOBSへ取り込みます。個人のシーンコレクション、画像、認証設定はGitへ含めません。

## 取り込み方法

このPCはOBS 32.1.2 / obs-websocket 5.7.3、VTube Studio 1.35.10です。Spout2プラグインは未導入で、OBS標準のゲームキャプチャを使用します。VTS公式には[通常のゲームキャプチャによる透過](https://github.com/DenchiSoft/VTubeStudio/wiki/Recording-Streaming-with-OBS#recording-with-obs-using-normal-game-capture-transparent-background)の手順があり、OBSも[透過を許可する設定](https://obsproject.com/kb/game-capture-source)を提供しています。

VTSの背景は画像背景からColor Pickerへ切り替え、RGBを黒 `#000000`、「透過(OBS)」をONにします。この版では色の保存値 `#000000FF` と `Config_LastBackgroundColorTransparent=true` が別になっています。設定値のAだけで取り込みの透過を判定せず、OBSで実際のalphaを確認します。通常のゲームキャプチャではVTSの操作メニューも写るため、設定後はメニューを閉じます。

OBSには専用の `Live2D（Revenant）` シーンと、`Revenant（透過）` ソースを追加します。既存のシーン・ソースと出力解像度を保持し、シーンコレクションの元データはローカルへバックアップします。

| 項目 | 設定 |
| --- | --- |
| 種類 | ゲームキャプチャ |
| モード | 特定のウィンドウをキャプチャ |
| 対象 | `VTube Studio:UnityWndClass:VTube Studio.exe` |
| 透過を許可 | ON |
| `premultiplied_alpha` | ON（この実機で合成を比較して選択） |
| カーソル | OFF |
| 他のオーバーレイ | OFF |
| フィルター | クロマキーを追加しない |

OBSの1920×1080・30fpsは既存値を維持します。モデルの配置と大きさはOBSの変換で調整でき、既存ソースとして別シーンへ追加できます。同じ名前のキャプチャを再利用すれば、VTSの取り込みを重複して作る必要はありません。

## 通信と状態の確認

既存の認証付きOBS WebSocketへ接続して設定します。パスワードはローカルの設定ファイルから処理内で読み、コマンド引数やログ、公開ファイルへ出しません。配信サービスの設定や配信キーは取得しません。

最初に配信・録画・仮想カメラが停止していることを確認しました。設定の検証ではモデル用ソースだけを撮り、本人のカメラ画像や既存のデスクトップ映像は保存しません。音声のミュート・音量も既存値を保持します。

## 使い方

1. CamoとVTube Studioを起動し、`Revenant_Polished` を読み込みます。
2. VTSのColor Picker背景・黒・透過(OBS)を有効にし、操作メニューを閉じます。
3. OBSの `Live2D（Revenant）` シーンでモデルを確認します。
4. 別シーンへ載せる場合は「既存を追加」で `Revenant（透過）` を選び、位置・サイズを調整します。
5. 花びらはVTSのF9または頭振りで散ります。自動再生には前回設定したローカル補助ツールが必要です。

モデルの顔・目・笑顔・物理はVTS側で動かし、OBS側は映像と透過を扱います。OBSで動かない場合は、VTSの追跡と映像自体が動いているか、対象ウィンドウがVTube Studioか、ソースが表示になっているかを順に確認します。

## 実機での最終確認

実OBSのゲームキャプチャを1602×1000 RGBAで取得しました。比較時の1枚では完全透明1,329,205画素、不透明237,753画素、半透明35,042画素があり、背景は実際に透明です。クロマキーフィルターは0個です。

OBSの一時的な色ソースをモデルより後ろに置き、白と暗灰色の両方へ実合成しました。緑の縁が消え、髪・ピアス・花の輪郭が残ることを確認しています。この実機では `premultiplied_alpha=true` を採用しました。OFF/ON比較の白髪の境界301画素ではRGB/alpha比の平均が約0.494→0.610へ上がり、二重のalpha乗算による縁の暗化を抑えています。比較の一時的な色ソースは削除しました。

既存のVTS花びらホットキーを一度呼び、OBSから開始・落下中・消滅後の映像を取得しました。花びら値は0→約0.275→約0.621→0へ進み、映像でも落下を確認しました。顔の合成入力は使っていません。この128フレームの区間ではOBSの描画スキップ0、30fps、平均描画時間約0.271msでした。長時間の配信性能を保証する試験ではありません。

VTSのCamo、モデル配置、修正版の物理・表情設定と、頭振り補助ツールは保持しました。OBSの元15シーン・53ソースとグループはローカルバックアップと比較し、元データが完全に同一でした。元シーンの順序も保持しています。

WebSocketで変更した設定がメモリーだけに残り、JSONには途中の値と削除済み背景が残っていたため、最後に保存を明示的に行いました。「シーンコレクション→エクスポート」は[保存先ダイアログを開く前に `SaveProjectNow()` を呼ぶ実装](https://github.com/obsproject/obs-studio/blob/32.1.2/frontend/widgets/OBSBasic_SceneCollections.cpp#L596-L605)なので、その操作を行い、ダイアログをキャンセルしました。

保存後、実APIとJSONのキャプチャ設定7項目が一致し、一時背景が残っていないことを確認しました。専用シーンには表示・固定したモデルソース1つだけがあり、現在シーンも `Live2D（Revenant）` として保存されています。配信・録画・仮想カメラは停止したままです。
