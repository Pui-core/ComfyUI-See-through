# 頭の傾きから髪の重力方向を分ける

髪全体が頭と同じ角度へ傾く場合、振り子の長さや遅れだけを変えても、止めた後の形は改善しないことがある。根元は頭に追従させ、毛先が下へ戻る形状と、その形状へ移る時間応答を用意する。

この版の見た目の確認後、[後ろ髪の振幅・横向き・ピアス・頬の調整](live2d-motion-balance.md)で後ろ髪だけの曲げを抑え、良かった襟足の動きを保持している。

既存の横向き用 `ParamHairFront` / `ParamHairBack` を大きく増幅すると、首を傾ける動きだけでなく左右を向く動きも過大になる。専用の `ParamHairGravityZ` を追加し、従来の小さな揺れと重力方向への補正を分ける。これは既存リグへ追加する設計例であり、任意のモデルで検証済みのプリセットではない。

## 既存リグへ追加する

1. `workspace_inspect` で対象の親と直接の形状軸を確認する。毛先を動かす親を保持し、原画、UV、メッシュ構造、表情・体の軸を変えない。
2. `author_axis` で既存の髪メッシュへ `ParamHairGravityZ` の −30 / 0 / +30 キーを追加する。既定値0の形状は維持する。
3. `physics_put` で頭Z角度を読む独立した振り子を追加する。従来の髪の振り子は、小さな慣性や左右差を担当する。
4. 根元と毛先を別々に計測し、頭を傾けて保持した時、動かしている時、停止した後を比較する。

[HairGravity.axis.json](../examples/nizima/HairGravity.axis.json) と [HairGravity.physics.json](../examples/nizima/HairGravity.physics.json) は、PSD2Live の `workspace_call` に渡す汎用リクエストの例。**Cubism の実行用 `.physics3.json` や nizima の直接読み込みファイルではない。** 操作が生成したモデルと physics3 を書き出して利用する。

実行前に `state` と `project_id` を現在の `workspace_inspect` 結果へ置き換え、`request_id` を新しい値にする。2操作目では1操作目の実行後に新しい `state` を取得する。メッシュIDとパラメータ範囲も対象モデルに合わせる。既に他の形状軸が直接結び付いている対象では、各組み合わせを調べ、必要な `shape.key` を明示する。親から継承する軸と直接の軸は区別する。

## 親の座標系に合わせて曲げる

`rig_deform` の `arc` は親ローカル座標を曲げる。長い髪でも親の座標が0〜1四方なら、その空間の角度をそのまま画面上の角度と見なせない。

親の横1単位と縦1単位が、描画時にそれぞれ `Mx` / `My` ピクセルへ対応するとする。中立姿勢で親の格子を評価して求めた `S = Mx / My` を使い、次の3操作を同じリクエスト内で行う。

1. 根元を支点に横だけ `S` 倍する。
2. `arc` で曲げる。
3. 同じ支点で横を `1/S` 倍して戻す。

これにより、縦単位にそろえた空間で曲げられる。JSON例の `S=0.5` と逆数2は説明用の値である。**対象メッシュ自身の縦横比ではなく、その親の座標から画面への倍率**を測る。親にせん断や非線形な変形がある場合、単一の倍率では近似になるため、根元付近の格子と複合姿勢も確認する。

`root` / `tip` / `pivot` は、操作開始時のローカル形状の bounds に対する正規化座標で、Xは右、Yは下。連続する操作は同じ bounds を基準にする。`root_pin` は root→tip の長さのうち固定する割合であり、秒数やメッシュ頂点数ではない。例の root `[0.5, 0.1]` と pin `.2` も解剖学的な付け根を自動判定する値ではない。

一方、`selection` は変形前の rest domain に対して評価される。曲げの root/tip の基準と混同しない。全体への等方化で固定領域も一時的に拡縮するが、同じ支点で逆変換するため、arcが動かさない領域は元へ戻る。丸め誤差を含む実際の根元変位は書き出し後にも測る。

## 重力用の時間応答

例は頭Z角度だけを読み、振り子の角度出力を `180/π` 倍して度単位の `ParamHairGravityZ` へ渡す。出力の符号と曲げ方向は、実際の頭の傾きで校正する。親の体Zなども大きく傾くモデルでは、頭Zだけで画面全体の重力方向を表せるとは限らない。

静止時の補正は長い襟足・後ろ髪を強め、短い前髪を控えめにする。振り子の `Delay` は遅延秒数ではなく積分に使う倍率なので、値の大小だけで「遅くなる」と判断しない。振幅を上げる前に、傾きを保持した時の平衡、ピーク、戻り、収束を時系列で比較する。無関係な常時揺れを抑える場合は、実行アプリ側の風も別に確認する。

## 横を向いた時の毛先も確認する

重力用の変形だけでは、頭Xだけを動かした時の小さな慣性は変わらない。既存の振り子が停止後に0へ戻ることを確認し、その出力が曲げる毛先の幅を補強する。[HairInertia.axis.json](../examples/nizima/HairInertia.axis.json) は既存 `ParamHairBack` を髪メッシュにも直接結び付ける例で、親の小さな揺れと合成する。新しい重力軸の各キーを `shape.key` に指定し、全6組み合わせを編集する。曲げ角度12度などは説明値で、短い前髪へ同じ強さを適用する設定ではない。

重力用の振り子へ頭Xを加えるだけで、移動中だけの慣性になるとは限らない。今回の小さなX入力の候補では、実行アプリでも横向き保持中に静的な偏りが残ったため採用していない。保持と停止の両方を測り、既存の時間応答を使う形状修正と区別する。

## 確認してから書き出す

- 頭Zの正負・中間・保持と、頭X/Y・体Zを組み合わせた時の根元、毛先の方向、長さ、顔との重なり。
- 重力パラメータ全範囲と従来の髪パラメータを組み合わせた時の反転、潰れ、非有限座標、過大な飽和。
- 動いている時の遅れ、停止後の余韻と収束。静止画だけで慣性の改善を判定しない。
- 公式CoreでのMOC読み込み・実座標と、実行アプリの同じファイルによる表示。編集ツールの成功応答だけでは合格にしない。
- 顔・体・装飾・花びら、UV、アトラス、既存モーションへの影響。アトラスを再利用する場合は元RGBAのSHAだけでなく、UV・ページ割当の一致も確認する。

個別の形状編集を優先し、全リグ再生成を修正の前提にしない。再生成が必要な場合は、別の作業コピーでUVや他部位への影響を確認する。具体的な曲げ角度・倍率・固定範囲と検証結果はモデルごとに記録する。

## 今回のローカルモデルの検証

PSD2Live 3.4.5で個別形状を保存し、公式Cubism Core 06.00.0513で新しいMOCを評価した。51パラメータ・58メッシュで、全UV・インデックス・中立座標は従来版と一致し、元の4KアトラスSHAも一致するため、対応する8K画像を保持した。

- 頭を約15度傾けて保持すると、後ろ髪の世界方向の変化は約14.6度から約3度、襟足は約14.5度から約1〜3度へ減った。短い前髪は約12度で、頭への追従を多めに残す。
- 左右27度の往復で、頭の動きだけを除いた毛先ピークは後ろ髪15.6→77.2元px、左右襟足約11→42〜43px。短い前髪は変更せず、停止後の余韻を既存の振り子から受け取る。
- 横揺れの根元帯の最大ずれは後ろ髪約.044元px、襟足約.00044px。根元帯は中立形状上端1.5%の幾何的な測定で、描かれた全接続点を表す値ではない。
- 毛先残差2元px以下への収束は後ろ髪約1.25秒、左右襟足約.8〜1.0秒。元の微小な残振動も増幅されるため、厳しい.5px基準では約3.5〜4.6秒になる。1.5秒後の残差は最大約1.41元pxで、表示解像度と分けて記録する。
- 重力軸両端×頭XYZ×既存髪7軸の6,912姿勢で、非有限・新しい反転・潰れ0、髪以外の座標差0。別の7,617姿勢の表情・口境界・装飾・花びら回帰でも新しい反転・閉口時の口内表示・耳の透明度異常0。

従来28グループの物理を保持し、重力グループだけを追加した。VTSではその風倍率0を保存し、再ロード後に読み戻す。重力の静的検証と横揺れの時系列は別に計測しており、数値だけで主観的な質感や本人の追跡精度を保証するものではない。

実VTSの9ケース・301サンプルでは新重力出力の最大17.65度・飽和0で、横向き保持後の新重力出力は0へ戻った。強い54度直接反転では既存の前髪出力が3サンプルだけ下限に達しており、全出力で飽和0とは扱わない。OBSの動作確認691フレームと花びら確認132フレームで描画スキップ0、透過と4枚の花びらを確認した。最終Camo観測は顔検出0/20で、合成入力を解除した本人追跡の最終確認は残る。カメラ映像は保存していない。
