# 前髪・後ろ髪・襟足の遅れと収束を整える

Issue #23の更新です。`Revenant_Natural` の髪だけを調整し、[首と体の追跡](live2d-natural-motion.md)と表情、装飾、花びら、原画を保持します。前のZIPと編集ソースはローカルへ退避してから更新します。公開Gitには汎用の部分設定と検証記録のみ含め、個人モデル・画像・設定・認証情報を含めません。

この時間応答の調整後も残った、傾けた頭と髪が同じ角度になる問題は、[重力方向へ戻す形状の追加](live2d-hair-gravity.md)で扱います。

## 同期した揺れと常時の微振動

元の左右襟足は物理の長さ・反応速度・収束・入力・出力倍率が全て同じで、左右の出力が完全に同期していました。前髪と後ろ髪も振り子の長さは違いますが、反応速度と加速度を含めた応答が近く、停止後の毛先peakが同じタイミングに出ていました。

VTSではモデル全体の風が6、髪7グループの個別倍率は全て1でした。頭の出力がほぼ0の静止状態でも、前髪は約±.031・後ろ髪±.035・左右襟足±.025が続きます。髪だけ風0にする短い比較で、前髪と縦揺れは約1e−7まで静まり、後ろ髪と襟足も過渡応答を含め約.007へ減少しました。静止時の小刻みな揺れは、風が主要因であると判断しました。

[Live2D公式の物理設定](https://docs.live2d.com/en/cubism-editor-manual/physical-operation-setting/)を参照し、長さだけで重さを決めず、反応速度・収束・出力を時間応答で比較します。PSD2LiveとCubism SDKのDelayは時間刻みに掛かる速度係数で、大きくすれば遅れるという意味ではありません。

## 髪7グループへの変更

前髪を早めに落ち着かせ、後ろ髪には遅れを残し、左右襟足は少し異なる応答へ分けます。振幅だけを大きくせず、停止後の余韻と静止する時間を整えます。

後ろ髪と襟足は体より頭主体の入力へ寄せ、縦揺れに横傾きが混ざる量を抑えました。対象7グループ以外の21グループ、出力先、1段振り子の構造は保持します。部位ごとの既存変形を使う調整で、毛束のメッシュを新設する変更ではありません。

[物理の部分パッチ](../examples/nizima/HairPhysics.patch.json)は既存IDへ`physics_put`を個別適用する値です。`settings_update`で全リグを再生成する必要はありません。[風の部分設定](../examples/nizima/HairWind.profile.json)は既存VTSプロファイルの当該配列へマージする例で、全プロファイルや他グループを置き換える用途ではありません。モデル全体の風6を維持し、対象髪だけを弱めます。

VTS APIの物理overrideは一時的で保存されず、`setBaseValue`も保存指定ではありません。短い切分けにのみ使用し、恒久設定は`WindMultipliersPerPhysicsGroup`の`ID`/`Value`へ保存して、再ロード後の値を読み戻します。[VTS公式API](https://github.com/DenchiSoft/VTubeStudio/blob/master/README.md#overriding-physics-settings-of-currently-loaded-vts-model)

## 形状を保った時間応答の検査

実PSD2Live 3.4.5のPhysicsEngineを60fpsで動かし、同じ確認済みMOCを公式Native Core 06.00.0513で評価しました。Naturalの実マッピングに合わせた半幅・全幅・正負・俯き・合成・Z保持を含む11シナリオ、各481フレームを旧新で比較します。Zを傾けたまま止める場合は、重力による静的偏りを残し、最終平衡との差で収束を測ります。

- 全シナリオで出力clamp0。顔・体の、同じ頭体姿勢に対する髪物理由来の変位は0。
- 幾何上の根元帯の最大ずれは約.0713→.0695元px。根元を滑らせず毛先へ変位が増えます。
- 半幅のZ入力で停止後の毛先peak遅れは、前髪.150→.117秒、後ろ髪.150→.233秒へ分離。
- 半幅Xで前髪のpeakは10.73→9.25元px、停止後に残差.5px未満へ収束する時間は.800→.567秒。後ろ髪はpeak7.16→7.10px、1.267→1.067秒です。
- 半幅Xの左右襟足出力相関は1.000→約.970。停止後の収束は左.667秒・右.817秒で、小さく戻る動きを保ちます。

根元帯は幾何の上1.5%、毛先は下10%を使う計測で、描かれた全接続点の可視性を証明する値ではありません。風による差は実VTS側で別途確認します。実機の見た目や本人の主観的な高級感を、この数値だけで保証しません。

MOCのSHAは `f453ab8e7963c571780f15d58eb98bec16257b7dfcfc381c245eb3cfe63aa560` のままです。物理だけを編集した書き出しでMOCの一致を確認したため、前回検出した花びらUVの退行を含む全リグ再生成は行っていません。旧新の物理JSONを深く比較し、髪以外の21グループとMetaが一致することを確認しました。

## 実VTube StudioとOBS

変更前後で、小さな左右振り・横傾き・頷きの同じ入力を再生し、VTSから155/156サンプルを取得しました。APIエラー0で、OBSのモデルソースだけを撮影しています。襟足の左右peakは同値.354から左.260/右.225へ分かれ、前髪のturn peakは.346→.353で動きを保っています。頷き後の静止では前後髪と襟足横揺れが0へ収束しました。Z停止直後の後ろ髪には余韻を残すため、全成分の短時間残留を一律に小さくする変更ではありません。

モデルアンロード完了を待ってから物理と個別風を保存し、同じModelIDで再ロードしました。7倍率を実APIで読み戻し、全体風6・base50・60fps・他21グループ・追跡マッピング・直前にユーザーが変更した配置が維持されていることを確認しました。アンロード応答だけを保存完了とみなすと古いプロファイルが後から書き戻されるため、実際の未ロード状態と保存後の値まで確認します。

花びらも再生し0→約.357→.747→0、OBS149フレームで描画スキップ0でした。合成入力を解除しCamoとNatural用補助ツール1プロセスへ戻しています。最終の実Camo20サンプルは顔未検出で中立へ戻る状態です。前タスクの20/20検出を今回の実追跡成功として再利用しません。カメラ画像のプレビュー・保存、配信・録画の開始は行っていません。
