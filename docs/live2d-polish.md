# 口・目・Z回転と髪、頭振りで散る花びら

首・体の動きを抑える追跡設定は [Issue #21の更新記録](live2d-natural-motion.md) を参照してください。

OBSへ透過で取り込む追加設定と実機確認は [Issue #19の設定記録](live2d-obs.md) を参照してください。

Issue #17の追加修正です。対象は前版 `Revenant_Dynamics`、更新版は `Revenant_Polished`。前版、原本PSD、ユーザーのグローバルカメラ設定を保持し、新しいモデルとプロファイルへ適用します。個人の画像・PSD・モデル・認証情報・端末パスはGitへ含めません。[前回の慣性調整](live2d-dynamics.md)も参照してください。

## 口・目・笑顔の感度

前回の閉口対策は、形状を開度0.12まで固定し、口内を0.15まで非表示にしていました。実Camo入力には0〜約0.09という採取区間があり、この設定では小さな開口へ反応できません。

今回、0.12の形状保持キーを削除し、口内・歯・舌はモデル開度0.025まで非表示、0.10で通常表示へ移します。口内の約5pxの閉口形は保ちます。認識入力は0.015〜0.45→モデル0〜1です。誤検出抑制と、小さく口を開けたときの反応を分けて調整します。

閉口時は消していた下唇の原画を表示し、約2.6原画pxだけ上へ寄せて上下の切断境界を接続します。実MOCでは下唇の肌が上唇の中央線を覆っていました。描画順の変更は編集画面には記録できてもMOCへ反映されなかったため、元画像の既存の口内切り抜き境界を数pxだけ広げ、下唇の陰影を残して上唇の線を見せます。別の口の絵へ置き換える修正はしていません。

| 入力 | 前版 | 更新版 |
| --- | --- | --- |
| EyeOpen→目開閉 | 0〜0.85→0〜1 | 0〜0.35→0〜1。0で完全閉眼を維持 |
| MouthOpen→口開閉 | 0〜1→0〜1 | 0.015〜0.45→0〜1 |
| MouthSmile→Smile | 0.60〜0.85→0〜1 | 0.72〜0.94→0〜1 |
| MouthSmile→口の形 | 0〜1→0〜0.45 | 0.55〜0.95→0〜0.5 |
| FaceAngleZ→顔Z | ±30→±20 | ±20→±30 |
| FaceAngleZ→体Z | ±30→±4 | ±20→±8 |

実Camoでは目入力の最大約0.289がモデル上で約0.304にしかならない区間を確認しました。笑顔の追加採取ではMouthSmile約0.530〜0.534で、旧設定は口の形を約0.24まで上げていました。新設定ではこの範囲のSmileと口の形は0です。ただし本人に表情を指定して分類した試験ではなく、笑顔判定の最適値という主張ではありません。厳しめを望むユーザー向けの調整値です。

## 顎線と原画

正面のFace形状を原画座標へ対応させた残差は最大約0.116px、顎の暗い輪郭2,151画素のメッシュによる欠落は0でした。原画の左輪郭には線が薄い区間と小さな凹凸があり、常時の切れ・歪みに寄与していました。

顔全体の形は変えず、左顎の局所だけ最大約1.4原画pxの輪郭補正を適用します。薄い線は隣接元画素の暗褐色を使い、原画の境界の内側を小さなブラシで接続します。原本PSDは変更しません。補修の実ブラシ検証では変更102画素、完全透明部分への追加0でした。原画座標y950〜980の31行を比較すると、暗い輪郭のない行は前版17行から補修後0行へ減っています。

4344²のキャンバスはPSD2Liveのブラシの16MP上限を超えます。原アプリを変更せず、私有の隔離起動で必要な4クラスの16MP定数だけを32MPへ変更して補修します。差分は4バイトで、32MP超の拒否は維持。原JARの不変と、ブラシ結果が元処理と一致することを検証しています。この制限変更はモデルの実行や通常の読込には不要です。

## Z回転、髪、ピアス、茨

公式Coreでは前版も顔Z±20に対して顔・眼の横線が±20°回っていました。顔ZがMOCに存在しない問題ではなく、VTS側の入力範囲と倍率を調整します。体はnative最大でも約1°の小さな回転だったため、`bodyZDegrees` を3→10へ増やしました。体に付く茨もこの変形を継承します。

前髪の旧物理はlength7.9 / mobility .77 / delay1.45で、反応が速く余韻が短い設定でした。11 / .92 / .57 / acceleration1.1 / scale1.65へ変更し、頭85%・体15%の入力を使います。`delay` は秒ではなく応答倍率なので、小さいほど緩慢です。根元の頭への接続を残し、毛先の変形量と遅れを増やします。

左右ピアスは形状振幅.065→.12、左右の振り子長を9/10に分け、mobility .93 / delay .54へ調整しました。左右が完全に同じ位相にならないようにし、上下方向の揺れも保ちます。不透明度は1のままです。

茨は首・腕とも体のZ/呼吸・体XYの親を継承することを確認しています。茨全体を頭へ接続する変更はせず、体への追従と既存の先端のしなりを組み合わせます。

最終physicsのSHA-256は `12b1b837c173bec3c0370923307cdbb6431ed765eb5cafc3154f0247e119ed0e` です。実Engineで28系統・30出力、60fps×481フレーム×10条件を評価し、144,300出力の非有限値は0でした。原生範囲の半分を使う8条件で出力の飽和は0、停止後は最長1.683秒で±0.02以内へ減衰します。全原生範囲XYZの同時stressでは一部が飽和するため、最大入力でも常に無飽和とは扱いません。

0.4秒で横を向き1.4秒で正面へ戻る入力では、頭停止0.1秒後も前髪の末端に約7.2px、ピアスに約4pxの変位が残ります。移動中のピアスの振幅は前版の約1.7〜1.8倍です。出力のピーク値だけでなく、公式Coreで根元に対する末端の座標を比較しています。

## 頭振りで花びらが散る

ユーザー指定は「花は残して花びらが散る」です。元絵の花びらから4枚を追加し、`ParamPetalScatter` で回転・落下・フェードを動かします。専用の体側の親へ接続し、散り始めの頭Zへの追従を落下とともに減らします。落下中ずっと頭に付いて動く構成にはしません。

`PetalScatter.motion3.json` は3.1秒の一度再生です。終端で完全に消してからstepで初期値へ戻し、上へ巻き戻る姿を隠します。頭・口・目・物理出力を書き換えません。F9で手動確認でき、自動検出は [ローカル補助ツール](live2d-petal-trigger.md) を使います。

頭の速い往復を検出し、対象モデルと顔検出を実行直前にも確認してから再生します。ゆっくりした顔向け、追跡の喪失・復帰、別モデルへの切替では発火を抑え、最低4.5秒の間隔を設けます。補助ツールはWindowsのユーザースタートアップへ設定し、同じプロセスの二重起動を防ぎます。トークンはローカルの本人ユーザーとSYSTEMに限定し、GitやモデルZIPへ含めません。

Node標準WebSocketでは実VTSの一部応答が空フレームになる問題を再現したため、`ws` 8.22.0を固定して使います。同じWindowsでInputList＋FaceFoundの応答中央値約13.7ms、最大約20.2msを確認しました。取得間隔の遅延を考慮し、800msを超える間隔では検出履歴を破棄します。11項目のテストには静止・ノイズ・低速、頭X/Zの往復、間隔313ms、追跡喪失、モデル切替の競合、通信エラーと再生抑止を含みます。

## 胸の過大な動き

追加指摘は「胸動かしすぎ。不自然」です。動作確認用の注入を停止した後も、11.22秒の実測区間で体XYZはほぼ0、呼吸だけが0〜0.5で周期変化していました。この区間の胸の動きは呼吸の変形に由来します。

原生の `breathLift` を0.8→0.25、`breathWiden` を0.6→0.15へ下げ、VTSの呼吸出力上限も0.5→0.35へ抑えます。組合せで上下変形は以前の約22%、膨らみは約17.5%になります。顔や体のZ回転は別の入力なので、この呼吸の修正で弱めません。

## 最終出力の検証

対象MOC3のSHA-256は `f453ab8e7963c571780f15d58eb98bec16257b7dfcfc381c245eb3cfe63aa560`。公式Native Core 06.00.0513で整合性を確認し、58メッシュ、38,044頂点、41,526三角形、50パラメータを読み込みました。

- 顔角度、左右独立の目、口の開度・形・笑顔、装飾、花びらを含む7,615姿勢を検査しました。非有限座標、不透明度の範囲逸脱、閉口時の口内・歯・舌の漏れ、耳の不透明度低下は0。顔・顎・目・口と、新しい花びらCの有意な新規反転は0です。
- 元モデル由来の首・腕の微小なスリバーは残ります。花びらAにも約0.000008px²の極微小collapseがあり、「全メッシュの全三角形が無反転・無collapse」という結果にはしていません。Cの再メッシュで見つかった約0.67px²の新規反転と、原生の細い三角形は分けて記録しています。
- 花びらの新しい101段階と頭Z−30/0/+30を検査しました。再メッシュでCの既存キーだけ760pxずれる問題があったため、全キーを補正して再検査しました。初期・終端は非表示、中間では花の近くから降下します。
