# 後ろ髪の振幅、横向き、ピアスの重力、頬の輪郭を調整する

Issue #29の更新。前回の[髪の重力修正](live2d-hair-gravity.md)に対する見た目の確認を受け、良い評価だった襟足を保ちながら、後ろ髪・横向き・ピアス・左頬の輪郭を調整する。個人モデル・PSD・画像・プロファイル・認証情報はローカルに保持し、公開Gitには汎用リクエストと手順・検証結果だけを保存する。

## 部位ごとに変更を分ける

| 対象 | 変更 |
| --- | --- |
| 後ろ髪 | 重力用の曲げ60→40度、既存慣性への追加曲げ15→5度。振り子の時間応答は保持する。 |
| 襟足 | 形状・振り子の時間応答・風を保持。横向き感度の増加分だけX入力を補正する。 |
| 顔の横向き | VTSの出力±27→±36。入力範囲±30と平滑化15は保持する。 |
| ピアス | 取付環と短い裏側を残し、長い金属部分を重力方向へ回す独立軸を追加する。 |
| 頬 | 元の輪郭にもある小段を、顔メッシュだけの局所変形で整える。通常顔と笑顔の両方を対象にする。 |

角度はこのモデルでの調整値であり、異なる親フレームや原画へそのまま適用するプリセットではない。横向きの感度を強めても、新たな横顔の原画が生成されるわけではない。実際の横顔・耳・瞼・口の表示を確認する。

## 感度と顔の遠近差を分ける

出力を±36へ増やすだけの候補では、顔幅が正面比約1%しか縮まず、鼻の顔中心に対する移動も約15pxだった。横移動が多く正面らしさが残るため、入力感度だけで十分とは扱わない。

既存の顔Warp・左右EyeShape・左右BrowShape・Nose/MouthShapeの7つについて、頭X両端×頭Y3キー×BodyLean3キーの全126形状を編集する。正面キーを変えず、全組み合わせを指定して上下向きや体傾きで修正が消えないようにする。

- 顔Warpは横を.92倍。遠い側の目と眉は.82倍、近い側は.98倍にして、瞼・白目・虹彩を共通の親で縮める。
- 鼻と口の既存の奥行き変形へ、横方向の差を加える。親の倍率と対象boundsから正規化移動量を求め、固定した原画px値を別モデルへ流用しない。
- HeadContainerを編集せず、髪・襟足・体の形状をこの遠近補強へ巻き込まない。原画・UVも保持する。

公式Coreで、頭X±36の顔幅は正面比約.925/.931、遠側白目の幅は約.76、近側は約.94、鼻の相対移動は約±29px、口は約±15pxになった。単一の正面画像から新しい横顔の描き込みを生成する修正ではなく、既存部品の遠近差を強める2Dリグ調整である。

横向きの出力を27→36へ増やすと、設定を触らなくても襟足の励振が増える。良かった動きを保つため、左右襟足の横振り子だけ、頭X入力の重みを75→56.25へ補正する（75×27/36）。体X・頭Z・体Zの重み、長さ・Mobility・Delay・Acceleration、縦振り子は保持する。同じカメラ入力に相当する旧HeadX27と新HeadX36で、出力時系列の一致を別に確認する。

## 既存の曲げを弱める

すでに変形したキーへ逆向きのarcを追加しても、操作ごとのboundsが変わるため、正確に振幅だけを減らせるとは限らない。後ろ髪は対象メッシュの既存2軸9フォームを保ったまま、明示した中立キーから他8キーの形状をコピーし、弱めた重力と慣性の曲げを各組み合わせへ再構築する。

対象を後ろ髪に限定し、襟足の軸・頂点・物理を編集しない。`keyform_apply copy` の `from` / `key` は対象の全直接軸を指定する。他の不透明度や描画順がキーごとに異なるモデルでは、全チャンネルを中立へコピーせず、必要な形状チャンネルと操作のschemaを確認する。全リグ再生成は必要ない。

## 金属を曲げず、接続位置で回す

元のピアス物理は動いていたが、頭を約15.2度傾けて保持すると、長い部分も約13.2〜13.3度傾いたままだった。揺れの接続切れではなく、重力へ戻す変形の角度容量が足りなかった。保存IRの直接軸が空という情報だけで接続切れと断定せず、公式Coreで実際の出力を評価する。

[重力軸の汎用例](../examples/nizima/EarringGravity.axis.json)は `author_axis`、[振り子の汎用例](../examples/nizima/EarringGravity.physics.json)は `physics_put` のリクエストであり、実行用physics3ではない。現在のstate/project_id/新しいrequest_id、対象ID、親の倍率へ置き換えて使う。例は片側で、反対側は別に測る。

- 親の1ローカル単位X/Yの描画倍率から縦横比を求め、横を一時拡縮して回転し、逆変換する。例の`.2`と`5`は説明値。
- 大きな取付環を動かさず、鎖の接続箇所を支点に、下部へ同じ回転変換を与える。髪と同じarcで金属棒を曲げない。
- 変形の選択範囲は横と下をrest domainの外まで広げ、上側の鎖部分だけに短いfeatherを置く。矩形の横端で金属の縁まで固定してしまう設定を避ける。
- 短い裏側の環は頭側に残す。全長の画像が裏側へ複製されていないか、アトラスと実メッシュの単独描画を確認する。
- `ParamEarringGravityZ` と専用振り子で頭Zを読み、角度を度単位へ変換する。既存Swing/Pitchは小さな慣性を担当する。VTSでは新グループの風倍率0を保存後に読み戻す。

## 原画と実メッシュで輪郭を照合する

添付の印に対応する位置を原画のアルファ・登録済み原画・公式Coreの輪郭で比較する。今回は顔の小段が元原画にもあり、Nativeの境界も元アルファの約0〜1px以内だった。欠損の原因をメッシュ反転だけに求めず、描かれた輪郭も確認する。

親の顔Warpを変えると耳やピアスまで動くため、顔メッシュだけへ局所変形を適用する。通常顔と笑顔で頂点・形状が異なる場合は、それぞれの形状へsource/UV点を三角形補間してランドマークを追従させる。同じbboxだけを見て両表情が同一形状と判断しない。鼻・目・口・反対側へ変形を広げず、補正幅と実画像を測る。

## 検証範囲

変更したMOCについて公式CoreでUV・ページ・トポロジー、非有限座標、姿勢ごとの新しい反転・潰れ、不透明度と根元を確認する。襟足の同一姿勢での完全一致と、後ろ髪・ピアス・顔以外への差も分けて検査する。元アトラスSHAとUVが一致した場合に限り、対応する8K画像を保持する。

実VTSでは新しい横向きの範囲、頭を傾けたままのピアス、停止後の揺れ、笑顔の輪郭を確認する。OBSはモデルソースだけを確認し、カメラ画像は保存しない。新MOCを使うため、花びら・閉口境界・耳の不透明度も回帰検査する。

最終MOCは52パラメータ・58メッシュ。公式Core 06.00.0513で13,680複合姿勢と7,619表情・口境界・瞼・装飾・花びら姿勢を検査し、新しい反転・潰れ・非有限値・閉口漏れ・耳の不透明度異常0。横向きの追加前後で髪・襟足・体の頂点は同じで、全UV・ページ・インデックスは元のまま。顔の正面4条件（通常/笑顔×開閉眼）は横向き追加前後で描画PNGも完全一致した。

- 後ろ髪の同一Yaw27での毛先ピークは77.2→35.1元px。新Yaw36でも約44.6pxで、以前のYaw27より小さい。
- 襟足は同じカメラ入力相当の旧Yaw27→新36で毛先ピーク差.034元px以内、振り子出力の丸め差は約1.5e−6以下。
- 頭±15.2度に対して長いピアスは約±1.6〜1.7度。取付環・短い裏側を維持し、全4枚の不透明度は1。
- 頬の修正は輪郭付近8頂点のみ、最大約2.46元px。通常顔・笑顔・左右向き・上下向きを実Coreと同じ8K画像で確認した。
- 実VTSで12ケース310サンプル、OBS760描画フレームと花びら137フレームでスキップ0、透過を保持。新ピアス重力出力は飽和せず、強い直接反転での既存HairBackの±1到達は別に記録した。

最終Camo観測は顔検出0/20だったため、本人追跡の最終確認は未実施。合成入力を解除してカメラ設定・配置・補助ツール1プロセスを通常状態へ戻し、元の表示位置を保持している。編集ソースと実行ファイル、配布ZIPを同じ最終版へ同期する。
