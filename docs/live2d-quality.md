# Live2Dモデルの品質修正とVTube Studioへの移行

閉口境界、肩・身頃のベルト、装飾の慣性、襟足、体の花と茨の追加修正は [素材別の動きの修正記録](live2d-dynamics.md) を参照してください。

対象は既存の `Revenant_Smile` からの品質改善です。Issue #13の作業記録として、素材の問題、リグの修正、検証できた範囲を分けて残します。原本PSD、既存の実行用モデル、編集用データは保持し、更新版は別名・別フォルダへ書き出します。個人モデル、画像、SDK、認証情報、端末固有の絶対パスはGitへ含めません。

更新版の名前は `Revenant_Refined` です。以前の配布版の読込成功を、今回の更新版の検証結果として使いません。原画の修復を含む完全な手作業のモデリングが完了した、という判定でもありません。

## 元の症状と原因

| 症状 | 既存モデルで確認した原因 |
| --- | --- |
| 唇・笑顔の口角が不自然 | 上下唇が周囲の肌を含む画像で、口内と別々の曲線・変形量を使っていた。口角と開口境界が揃わず、肌まで大きく変形した |
| 耳たぶがずれる | 顔の肌土台にも耳が描かれ、独立した耳画像と重複していた。顔と耳が異なる親変形に属していた |
| 前髪と顔の向きが合わない | 前髪にも顔角度は接続されていたが、顔・前髪・髪飾りの移動量と奥行き変形が異なり、相対的に滑った |
| 二重線が閉眼時に角張る | 上まぶたはまつ毛・肌・二重線が一体。自動閉眼が肌全体のアルファ重心をまつ毛の中心と扱い、少ない頂点で曲げていた |
| 上下まぶたが途切れる | 下まぶたを `face_detail` としただけでは閉眼に追従せず、上まぶたとは顔角度の親変形も異なった |
| 閉眼時の白目・瞳の欠け | 既存の白目を極細の曲線へ圧縮した際、公式Coreの座標で左右14/15三角形の反転を確認した |
| 花・花びらが髪からずれる | 頭部には属するが、前髪とは異なる変形を継承していた |
| 顔を下げても揺れが出ない | 既存の物理演算10系統に `ParamAngleY` が入力されていなかった |
| ピアスが揺れると薄くなる | 揺れ単独では不透明度1。顔の左右端で遠い側が約0.8085になり、耳のフェードをピアスも継承していた |

既存のアトラスは4096×4096pxが2枚で、UVとモデル座標の比較では概ね原画と同じピクセル密度でした。顔素材自体は671×952pxです。画質はアトラス寸法だけで判断せず、変形の粗さ、部品のずれ、原画の白縁なども確認します。アトラスの拡大だけで原画の細部が増えたとは扱いません。

## 修正の要点

- 耳とピアスの表裏を `DeformFaceContour` へ `space=canvas` で接続し直す。静止位置と既存キーを保ち、顔の肌土台と同じ変形へ揃える。耳のフェードは0へ変更する。ピアスの揺れを再作成し、上下向きの入力も追加する。
- 下まぶたを左右それぞれの `DeformEyeShapeL/R` へ接続し、対応する `ParamEyeLOpen/ROpen` に連動させる。`ParamSmile` の有無を含む組合せで確認する。
- 上まぶたのメッシュを局所的に細分化する。今回の設定は `maxEdgeDistance=6`、`interiorDensity=10`。このモデルのdocument単位は原画ピクセルと同一ではなく、約2.12倍の換算があるため数値を他モデルへ流用しない。
- 上まぶたの閉眼形は開眼キーをコピーして作り直す。縦方向の縮小、滑らかな曲線、移動を組み合わせ、肌と二重線の急な折れを抑える。メッシュ再構築は既存キーを補間して移行するため、細分化だけで旧形状の角張りは消えない。
- 白目の閉眼形を開眼キーから作り直し、縦方向4%の単純な帯へ縮めて反転を防ぐ。最終閉眼では白目を非表示にし、瞳も閉じ切る直前の15%でフェードさせる。中間開度での連続性を別に確認する。
- 前髪の `frontHairPerspective` を10→4、`frontHairTurn` を2→1、`frontHairTilt` を0.6→1.4へ変更し、顔に対する追従量を調整する。Native Coreで左右方向と俯き方向が顔と揃うことを確認する。
- 髪飾りと花びらを前髪の物理変形へ接続し、装着部分を保った小さな揺れを追加する。
- 顔の上下向きを髪・ネックレスなどの適切な物理入力へ加える。うなずきが過度な横揺れにならないよう、上下方向の形状と入力の強さを調整する。

上下唇を口内と同じ `DeformMouthShapeBoth` へ接続し、角度による位置ずれを抑えます。笑顔の強すぎる曲線を減らし、閉口では口内と下唇の重なった黒線を非表示にして上唇の線へまとめます。閉口・半開・全開と笑顔を画像で比較しています。元の肌パッチとハイライトを使うため、口周辺の原画自体の描き直しは実施していません。

最終4096pxアトラス2枚へ、既存UpscaylとAnimeVideo v3の2倍処理を適用し、8192px RGBAを2枚作成しました。透明部分へRGBを延長してからRGBだけを推論し、alphaは元画像から独立してbicubic拡大します。各67,108,864画素のalpha比較で期待値との差は0でした。超解像前後でMOC3とUVは同じです。編集用CMO3内の原画は元の解像度です。

操作の実装は [PSD2Live v3.4.5](https://github.com/tsunehimatoi/psd2live/tree/v3.4.5) を参照しました。メッシュの変形親変更には `object_edit_appearance` の `bind` を使います。`rig_edit_structure` のmesh `move` はPartsツリーの整理であり、変形親の変更とは異なります。

最終MOC3のSHA-256は `f91d62eb2adcabc061ce9cf90053b2a283a1b61ac9af3faa80502110646d0452` です。俯き入力−25°を1.5秒保持・解除する物理試験では、髪・ネックレス・左右ピアスの縦揺れ4系統が反応し、解除後に収束しました。

付属の汎用設定ツールは、モデルのDisplayInfoに存在するパラメータだけをVTS入力へ接続します。既存profileは既定では上書きしません。

```sh
node tools/prepare-vtube-config.mjs /path/Revenant_Refined.model3.json
```

`AccessoryDemo.motion3.json` は顔の左右・傾き・俯きと身体の動きだけを入力し、揺れの出力パラメータを直接上書きしません。

## 導入したスキル

取得元は [Ariakage/live2d-agent-kit](https://github.com/Ariakage/live2d-agent-kit)、固定した版は [`94e79e3a94753ae1bd29204d3ed685a3c7b59022`](https://github.com/Ariakage/live2d-agent-kit/tree/94e79e3a94753ae1bd29204d3ed685a3c7b59022) です。公式のskill-installer helperへ次の引数を渡して導入しました。

```text
--repo Ariakage/live2d-agent-kit
--ref 94e79e3a94753ae1bd29204d3ed685a3c7b59022
--path .
--name live2d-agent-kit
```

通常のスキル一覧へ反映するにはCodexの再起動が必要です。この作業では導入済みの `SKILL.md` を直接読み、既存原画を保つこと、座標系を区別すること、実Core検証と見た目・カメラ検証を混同しないことを適用しています。

スキル内のエンジンpinは `5526f2e16b57e5f83d34f33730d6fa26d8bc8695` と累積パッチを前提としますが、今回の既存モデルの修正はPSD2Live v3.4.5配布版で続行しています。別エンジンへの置換は行っていません。超解像ではスキルのalpha処理を使用しました。スキル導入そのものはモデル品質の合格判定ではありません。

## VTube Studioと配信時の透過

PCのWebカメラで使用する候補としてVTube Studioを選びます。[Steam公式ページ](https://store.steampowered.com/app/1325860/VTube_Studio/) は全機能を無料で使えると案内しており、Webカメラ追跡中は透かしが表示されます。透かしの除去は任意の有料DLCです。無料のPC利用と、スマートフォン側のPRO機能・接続制限は分けて扱います。[公式FAQ](https://github.com/DenchiSoft/VTubeStudio/wiki/FAQ) も参照してください。

笑顔はVTSの `MouthSmile` をモデルの `ParamSmile` へ対応させ、認識値に合わせて滑らかに変形させる構成です。固定の表情ファイルをホットキーで呼ぶ操作とは別です。ユーザーが指定したCamoを選択し、Webカメラの開始hotkeyをVTS APIで呼ぶと顔検出と実入力が動作しました。最終閾値の確認後に実カメラへ復帰し、12点すべてで顔検出と角度の追従を確認しています。実MouthSmile約0.528でParamSmileは0を維持しました。

実入力の笑顔値が約0.52だったため、0.5付近を通常顔として扱えるよう最終presetの笑顔入力は **0.60〜0.85→0〜1** としました。本人がその時に笑っていたかは数値だけでは判断できません。本人が普通の顔でキャリブレーションし、笑顔の感度と通常顔へ戻ることを確認してください。Camoには映像配信が停止するログもあったため、映らない場合はCamo Studioとスマホ側の接続を確認します。

WindowsのOBSでは、VTSのColor Picker背景で `Transparent in capture` を有効にし、アルファを保つSpout2または対応するゲームキャプチャを使う方法を推奨します。緑背景を色で抜く方法では、境界や細い装飾まで消えることがあります。モデルの不透明度修正とOBSの合成設定は、それぞれ確認してください。手順は [VTube Studio公式のOBS案内](https://github.com/DenchiSoft/VTubeStudio/wiki/Recording-Streaming-with-OBS) を参照してください。Spoutと透過の設定フラグは有効ですが、開いた案内に単色背景への切替が拒否されたため、背景切替は未設定です。OBS側の追加プラグイン導入や合成確認も行っていません。
