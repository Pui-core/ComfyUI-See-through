# 閉口境界と衣装・装飾の遅延の修正

Issue #15の記録です。更新モデルは `Revenant_Dynamics`、前版は [Revenant_Refined](live2d-quality.md) です。原本PSDと前版を保持し、実行用・編集用データを別フォルダへ保存します。個人モデル、画像、SDK、認証情報、端末固有のパスはGitへ含めません。

## 表示を妨げていた画像

モデル前面へ `background_8.png` という独立したPNGアイテムが重なっていました。VTube Studioの一覧では前髪へpinされていました。対象インスタンスを解除し、再起動時のアイテム復元設定からも同インスタンスを外しています。元画像は保持しました。モデル専用画面の撮影でも、緑画像がなく衣装が見えることを確認しています。

## 閉口付近の口内

前版には、全開時の高さを保った口内を口開閉値だけでフェードする経路がありました。小さな入力で大きな口内画像が薄く現れる原因でした。舌と歯には別の不透明度があり、口内の透明度だけを変えても漏れを防げません。

- `ParamMouthOpenY` が0〜0.12では、口内を中立時約5pxの帯へ縮め、上下唇も閉口形状を保ちます。
- 口内・舌・歯と重複する下唇を0〜0.15で非表示にし、0.15〜0.20で表示へ移します。上唇の線は維持します。
- 口形−1/0/1と笑顔0/1にも同じ境界を設定します。

最初の約2pxの帯では、強い顔角度で隠れた口内に小さな反転がありました。帯を約5pxへ広げ、表示開始を0.15へ調整した最終版では、閉口付近の500組合せで口内の反転が0になりました。高さは顔角度によって変わるため、固定の8px上限は検査基準に使いません。この閾値は本モデル用で、他の認識器やモデルへそのまま流用しません。

## 素材と接続点ごとの動き

| 部位 | 変更 |
| --- | --- |
| ネックレス・垂れた金具 | 体主体の入力へ変更。左右と上下の応答を遅くし、停止後の余韻を残す |
| 左右ピアス | 頭主体の入力を維持。根元を保ち、小さな曲げと減衰で金属の慣性を調整 |
| 肩ベルトとリング、身頃ベルトとリング | 接続する布と金具を同じSwingへまとめ、左右方向を根元・先端の2段にする。別々の遅延による取付部の分離を避ける |
| 袖タグ・反対側の金具・腰チェーン | 体主体の入力と長めの振り子へ調整。腰チェーンの両端固定は保つ |
| 後ろ髪 | 顔の左右で逆へ滑る量を抑え、頭への追従とその下の物理揺れを分ける |
| 左右襟足 | 画像ごとの変形面へ分け、各根元を固定。毛先へ左右・上下の揺れを付ける |
| 首・腕の花、裾の花びら | 花の局所的な回転と、部位ごとに異なる周期の物理を追加 |
| 体の茨・蔓先 | 花の動きとは別のパラメータで、付け根から先端へ増える小さな曲げを追加 |

ベルトは、length7＋7、根元側mobility .86 / delay .60 / acceleration1.4 / scale1.0、先端側 .82 / .65 / 1.8 / scale .7です。2段の角度は親segmentに対する相対角であり、同じパラメータを2段から上書きしません。布の接続辺を固定し、左右振幅は肩側.045、身頃側.035へ抑えました。上下方向にも小さな変形があります。

ネックレスの設定はlength14 / mobility .92 / delay .60 / acceleration1.0 / scale1.5、ピアスは8 / .91 / .58 / 1.2 / 1.4です。体側の左右入力はBody X85%とHead X15%、傾きはBody Z75%とHead Z25%を基準にしています。後ろ髪は16 / .94 / .65 / 1.1 / 1.8で、襟足は別の左右・上下出力です。

花は初回の強い局所変形で大きな三角形の反転が見つかり、不採用にしました。最終形では首・腕の回転を約4°以下へ抑え、選択境界のfeatherを広げ、hardnessを下げています。花・茨は原画内で一枚の画像につながっているため、独立した花びらを裏側まで描き足したものではありません。

## 単位と検査方法

[PSD2Live v3.4.5](https://github.com/tsunehimatoi/psd2live/tree/v3.4.5) の導入済みPhysicsEngineを、GUIとは独立したプロセスで実行しています。出力パラメータの時間変化を公式Cubism Coreの座標へ合成し、末端が根元に対して逆方向へ残ることも検査しました。実装は [公式Native Framework](https://github.com/Live2D/CubismNativeFramework/blob/develop/src/Physics/CubismPhysics.cpp) と [物理設定の説明](https://docs.live2d.com/en/cubism-editor-manual/physical-operation-setting/) を参照しています。

| 値 | この実装での意味 |
| --- | --- |
| `length` | シミュレーション内の振り子長。原画の形状長とは別 |
| `mobility` | 次の計算へ保持する速度の係数 |
| `delay` | 応答の倍率。秒数ではなく、内部では `delay × dt × 30`。小さいほど緩慢になる |
| `acceleration` | 重力方向の復元力 |
| Angle出力の`scale` | radiansからパラメータへの倍率。入力側のAngle正規化はdegreesだが、本モデルの±1出力へdegrees変換として57.3倍を追加しない |
| `Weight` | 入出力の影響率。独立した質量パラメータではない |

VTSの `baseStrength=50` はCubism Editorと同等の既定値で、振幅が半分という意味ではありません。検査ではnonlegacy・60fpsを基準にします。[VTS公式API](https://github.com/DenchiSoft/VTubeStudio/blob/master/README.md#getting-physics-settings-of-currently-loaded-vts-model)

## 最終版の検証

対象MOC3のSHA-256は `624c15b36c96b0595a4c2a588a239652fcbaf0229e9b995e5cb9dcabe92dd29f` です。公式Native Core 06.00.0513で整合性を確認し、54メッシュ、37,954頂点、41,438三角形、49パラメータを読み込みました。

- 原本PSDは未変更。前版とUV・三角形の接続・テクスチャ割当が一致し、4096pxの元アトラス2枚も完全一致しています。そのため、前版でalphaを独立検証した8192px RGBAアトラスを再利用しています。超解像だけで原画の細部が増えたとは扱いません。
- 顔角度・表情・素材の変形を含む5,516ポーズで有限座標と耳・ピアスの不透明度を検査。閉口810組合せで表示漏れ0、開き始め付近の別検査500組合せで口内の反転0です。花・茨には細い三角形の微小な符号反転が残り、複合条件の最大面積は約1.614px²、単独条件の最大厚みは元画像の約0.753pxでした。大きな花の折返しと、この残存する細部は区別して記録します。
- 28物理系統・30出力を60fps、各8秒、10シナリオで評価しました。原生範囲の半分を使う正負の瞬間入力・滑らかな入力・複合入力8シナリオでは、非有限値0、出力飽和0です。停止後は最大約1.68秒で出力±0.02内に収束します。8秒時の最大残留は後ろ髪の約±0.0087で、完全な0という判定ではありません。
- 全原生範囲を同時に動かす複合stressでは一部出力の飽和が残ります。実際のVTSは頭X±30/原生±45、体X±5/±10などのマッピングであり、stressと実トラッキングの入力幅は異なります。風・強度・入力幅を変えれば検証条件も変わります。
- 実Core合成では、右へ動く根元に対し、開始0.2秒時に末端が左へ残ります。相対変位はネックレス約−4.68px、ペンダント−7.67px、ピアス約−5.1〜−5.4px、肩リング−7.82px、身頃リング−6.46px、襟足約−6.7〜−6.8pxでした。単に出力の絶対peakを見る方法にはしていません。

`MaterialDemo.motion3.json` は8秒間の顔・体の標準入力6種だけを動かします。物理出力を直接上書きしないので、取付点・遅れ・減衰の確認に使えます。メタデータの114区間・120制御点を実配列と照合し、最終physicsでDemo自体を8秒再生した30出力も非有限値・飽和0でした。

残存する微小反転の代表4箇所は、元の座標・UVと4倍拡大の再描画を比較しました。大きな花弁や葉の欠落は見えず、両面描画のため裏返りが即座にカリングの穴になる設定でもありません。ただし該当画素は完全透明ではなく、作者側の細い三角形にも反転があるため、表示への影響0やMOC丸めだけが原因とは判断しません。

VTS 1.35.10へ同じ最終MOC・アトラスを導入し、口開度0/.02/.08/.12/.15/.20/.50/1を実際の表示で確認しました。0〜.15は口内が漏れず、.20から開口します。F8でDemoが発火し、ネックレス・ピアス・2段ベルト・花・茨・襟足が反応しました。別の連続X入力試験では52サンプルを約16.3秒取得し、HeadX約22°、BodyX約3.66°の入力と停止後の減衰を確認しています。

引き継いだユーザープロファイルのHeadXだけに `UseBlinking` と `UseBreathing` が混入していたため、更新版のその2項目をfalseへ戻しました。呼吸用の `ParamBreath` は維持し、前版プロファイルは変更していません。笑顔入力 .60〜.85、nonlegacy・60fpsを保存しています。比較中だけ風0とし、終了後はユーザー設定の風6へ戻しました。

合成入力を停止しCamoへ復帰しました。トラッカーは起動し1280×720@30の受信ログがありますが、最終時点の `faceFound=false` です。今回の数値試験を本人の笑顔・目閉じの認識精度の証明には使いません。モデルだけの画面を保存し、本人のカメラ映像は保存していません。OBSでのアルファ合成は今回も未検証です。
